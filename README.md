# Workline

AI(Muse など)の作業を、MCP で受け取ってリアルタイムに表示するビューアーです。

- 送信: MCP(Streamable HTTP)。AI がタスクごと・ステップごとに細かく送る
- 複数の AI に対応: 送信時に AI 自身が名前・モデルを申告し(`agent`)、サーバーが公式サイトのアイコンを取得して表示する
- 配信: WebSocket(Durable Object)。切れている間は 5 秒ごとの取得に切り替わる
- 構成: `src/worker.js`(MCP サーバーと配信)+ `src/agents.js`(AI の申告とアイコン取得)+ `public/index.html`(ビューアー 1 枚)
- 保存: Durable Object の SQLite(新しい 100 件、30 日まで。件数はルートタスク単位で、子タスクは件数に入らない)
- 親子タスク: サブエージェントは `parentTaskId` で親の配下に入り、番号(00=メイン、01…=サブ)はサーバーが召喚順に振る

Muse への接続方法は [MUSE_GUIDE.md](./MUSE_GUIDE.md) にあります。

## デプロイ(GitHub から)

1. このフォルダを GitHub のリポジトリにする(例: `zixiang0623/Workline`)。
2. Cloudflare の Workers & Pages で「Import a repository」からそのリポジトリを選ぶ。
   ビルドコマンドは空のまま、デプロイコマンドは `npx wrangler deploy`。
3. 設定の「Variables and Secrets」に、シークレットを 2 つ追加する。

   | 名前 | 役割 | 未設定のとき |
   | --- | --- | --- |
   | `MCP_TOKEN` | 書き込み(MCP)に必要 | URL を知っている人は誰でも送信できる |
   | `VIEW_TOKEN` | ビューアーの閲覧に必要 | URL を知っている人は誰でも閲覧できる |

4. 発行された `https://workline.<あなたのサブドメイン>.workers.dev` を開く。
   MCP の URL はそれに `/mcp` を付けたものです(ビューアーの空画面にも表示されます)。

v1.0 から更新する場合も、保存済みのデータはそのまま使えます(列は起動時に自動で追加されます)。ただし `startTask` に `agent` が必須になったので、AI 側の依頼文を差し替えてください。

初回デプロイで Durable Object のマイグレーション(`wrangler.jsonc` の `migrations`)が自動で適用されます。

## ローカルで動かす

```bash
npm install
printf 'MCP_TOKEN=test\nVIEW_TOKEN=test\n' > .dev.vars   # 省略可
npx wrangler dev
```

`http://localhost:8787` を開き、別のターミナルから送信して確かめます。

```bash
curl -s -X POST http://localhost:8787/mcp \
  -H "content-type: application/json" -H "authorization: Bearer test" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"startTask","arguments":{"title":"テスト"}}}'
```

## エンドポイント

| パス | 内容 |
| --- | --- |
| `/` | ビューアー |
| `/mcp` | MCP サーバー(POST のみ) |
| `/ws` | ビューアー向け WebSocket |
| `/api/snapshot` | 現在の状態(JSON) |
| `/api/icon?agent=<id>` | 申告された AI のアイコン画像(初回に取得して保存) |
| `/api/purge` | ログの全消去(POST、人間が画面の手順を通ったときだけ。下の「ログを消す」を参照) |
| `/api/health` | 死活確認 |

## ログを消す

左下の「ログをすべて消去…」から、保存されているタスク・ステップ・AI・アイコンをすべて消せます。
間違って消さないよう、わざと手順を長くしています。途中でやめても、何も消えません。

1. 確認: 消える件数(タスク・ステップ・AI)を見る
2. 人間確認: 足し算の答えを入力する(署名つきで、10分で失効)
3. パスワード: `VIEW_TOKEN` を入力する(未設定なら `MCP_TOKEN`)
4. 名前をなぞる: 残っているAIの名前が薄く出るので、1つずつなぞって描く(なぞれた割合75%以上、はみ出し20%以下)
5. 入力: 半角の小文字で `delete` と書く(貼り付け不可)

- AI(MCP)からは消せません。消去用のツールはありません。
- サーバー側でも、人間確認・パスワード・`delete`・「いま残っているAIの名前が全部そろっているか」を確かめます。なぞる手順だけは画面側の確認です。
- `VIEW_TOKEN` も `MCP_TOKEN` も未設定の状態では、誰でも消せてしまうので、消去そのものが無効になります。先にシークレットを設定してください。
- 消去すると、開いている他のビューアーの画面も同時に空になります。

## 親子タスク(サブエージェントの並列表示)

- 左の一覧は、親子のツリーです。終わった子は畳まれ、実行中の子は常に見えます(「一覧」ボタンでフラット表示に切り替えられます)。
- ルートタスクを開くと、セッションの画面になります。
  - 「いま働いているメンバー」: 実行中のエージェント全員が、番号・名前・モデル・いまの状況・経過時間つきで並びます。
  - レーン: エージェントごとに1行。時間軸をそろえてあるので、帯が重なっている時間帯は並列で動いていたとわかります。レーンを押すと、そのエージェントの詳細に移ります。
  - 「子 4/5 完了」と全体の経過時間。親が先に終わっても、子が続いていれば「親は完了。子はまだ実行中です」と出ます。
  - ステップの一覧は、「このエージェント」と「全員(時系列)」を切り替えられます。
- 5分間、何も届かない子は淡色になり、実行中の数から外れます(自動で失敗にはしません)。
- バッジは「番号 + アイコン + 名前 + モデル名」です。モデルが違うと、番号の色が変わります。

## ビューアーの機能

- 実行中の「いまやっていること」と「次」を上部に固定表示。進捗バーと、予定チェックリストに連動(広い画面では予定を右の列に固定)
- 実行中のステップは色つきの帯で強調、失敗は赤の帯。新しいステップは届いた瞬間にふわっと光る
- 上部に「N件実行中」(全AI合計)。90秒以上更新がないタスクは、一覧のアイコンが警告色になる
- 時刻つきのステップ一覧(新しい順 / 古い順の切り替え、前のステップからの経過、実行中ステップの経過時間)
- 90 秒以上更新がないと警告
- 失敗したステップは赤で表示、URL は自動でリンクに
- AI ごとの名前とアイコン(取得できないときは頭文字)。2 つ以上の AI が送信すると、左に絞り込みと実行中のタスク数が出る
- 別の AI(サブエージェントなど)が行ったステップには、その AI の名前とアイコンが付く
- タスク一覧、「最新を追う」、ログのコピー(Markdown)、通知音(初期はオフ)
- 幅 60rem 未満ではタスク一覧がドロワーになり、スワイプで閉じられる

## AI用司令文
次のMCPサーバー(Streamable HTTP)に接続してください(カスタム連携が必要なら作ってください)。
URL: https://workline.zixiang0623.workers.dev/mcp
認証: トークンを設定している場合は Authorization: Bearer <トークン> ヘッダーで送ります(トークンは安全な認証情報ストアに保存してください)。
接続できたら、これ以降の作業は、このサーバーのツール(startTask / addStep / updateStep / setStatus / finishTask)に細かく送信しながら進めてください。
- startTask の agent に、あなた自身を申告する。例: { "name": "Muse", "model": "Muse Spark 1.3", "domain": "muse.ai" }(domain は公式サイト。画面のアイコンに使います)
- 小さな行動のたびに addStep を呼び、作業が終わったら finishTask を呼ぶ。
- パスワードやAPIキーなどの秘密情報は送らない。
